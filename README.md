# 유승주

React·TypeScript로 화면을 만들고, 성능 개선을 수치로 검증하는 프론트엔드 개발자입니다.  
서체 내려받기를 페이지 진입 후 913ms에서 149ms로 앞당기자고 제안해 수치로 확인했고, 파트 간 문의 105건이 오간 이슈 보드를 만들었습니다.

## 만드는 방식

- **처음에는 검증 가능한 작업만 넘겼습니다.** 검사로 확인할 수 있는 초기 세팅은 맡기고 화면 구조는 직접 정했습니다. 이후에는 디자인 시안도 맡겨, 만든 화면을 보고 판단하는 쪽으로 기준을 바꿨습니다.
- **화면 검증이 제게 몰린 것을 한계로 봅니다.** 자동 검사를 통과해도 화면에서 어색한 부분은 남았습니다. 직접 보는 판단을 대신할 절차가 부족해, 제가 열어 본 화면만 확인되는 병목이 남아 있습니다.
- **팀에 나가는 말은 제 승인 뒤에 두기로 했습니다.** 코드가 맞는지와 제가 내용을 알고 팀에 보내는지는 별개라, 이슈와 리뷰 요청은 초안을 확인한 뒤 올리는 것을 기준으로 정했습니다.

여러 에이전트에게 일을 나누자 제 응답을 기다리는 일과 같은 기능을 중복으로 만드는 일이 생겼습니다.
그래서 작업을 조율하는 세션과 구현하는 세션을 나눴습니다. 조율에 학습 대화까지 섞여 문맥이 길어진다고 느껴 학습 세션도 따로 뒀고, 설명은 노트에 남기게 했습니다.
처음부터 정해 둔 구성이 아니라, 일하다 걸린 문제에 따라 바꾼 구조입니다.

공개된 규칙과 작업 절차는 [PinLog 하네스](https://github.com/Team-PinLog/front/blob/dev/AGENTS.md)에 있습니다.
